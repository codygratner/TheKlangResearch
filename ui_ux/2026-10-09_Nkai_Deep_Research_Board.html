1.0 Dynamic Data Loading: The file:/// CORS Wall & The Universal Adapter Architecture

The Problem: Inlining roadmaps into every HTML artifact inflates file sizes from 35KB to 180KB+ and burns thousands of generation tokens. However, calling fetch('roadmap.json') inside a local file:/// page triggers an immediate, uncatchable Chromium security rejection (origin: 'null').

❌ Why Raw fetch('file://') Fails RFC 6454

Chromium assigns opaque origin null to local files. The Fetch API explicitly rejects non-HTTP protocols, causing silent blank screens in offline webviews without zero-flag workarounds.

✅ The Hybrid Universal Adapter SOTA Pattern

In Antigravity Extension mode: uses Node.js Sidecar SDK / HTTP IPC.
In Standalone file:// mode: dynamically injects data/roadmap.data.js via a synchronous script tag. 100% CORS-proof, zero build tools.

// Universal Dual-Mode Loader Pattern (core/data_loader.js) class NkaiDataLoader { static async load(key, scriptPath, apiPath = `/api/${key}`) { window.NKAI_DATA = window.NKAI_DATA || {}; if (window.NKAI_DATA[key]) return window.NKAI_DATA[key]; // Mode 1: Antigravity Extension / Node.js HTTP Server if (window.location.protocol === 'http:' || window.sidecar) { const res = await fetch(apiPath); return (window.NKAI_DATA[key] = await res.json()); } // Mode 2: Zero-Dependency Offline file:/// Mode return new Promise((resolve, reject) => { const script = document.createElement('script'); script.src = scriptPath; script.onload = () => resolve(window.NKAI_DATA[key]); script.onerror = () => reject(new Error(`Failed to load ${scriptPath}`)); document.head.appendChild(script); }); } }

5.0 Sidecar Upgrade Path & Ecosystem Migration Ledger
Migration Ledger SemVer v1.1.0

The Architectural Dilemma: As N'kai evolves into a transcendent developer cockpit—introducing dynamic data loaders, slide-over utility drawers, cache-busting refresh, Web Audio haptics, and 2x2 decision matrices—our existing fleet of sidecars (ui_ux_research_board.html, roadmap_sidecar.html, ecosystem_ideas_research_board.html) must upgrade smoothly without manual rewriting, losing custom research content, or breaking offline file:/// portability.

5.1 The Three Architectural Upgrade Models
Model 1: Decoupled Core Fragile

Mechanism: HTML files link to external ../core/sidecar.css and sidecar.js via relative paths.
Pros: Edits to core instantly propagate to all past and future boards.
Cons: Destroys atomic portability. Moving an artifact into brain/<conversation-id>/ or zipping breaks relative paths, leaving a blank unstyled document.

Model 2: Manual Inlining High Friction

Mechanism: Every board remains 100% self-contained with inlined CSS/JS. Upgrades done by manual cut-and-paste.
Pros: 100% offline atomic durability. Never breaks when moved.
Cons: Immense friction. Upgrading 100KB files manually leads to unclosed tags, copy-paste errors, and massive developer drag.

Model 3: Hybrid Pragmatic Recommended

Mechanism: Modular core in nkai/core/, compiled template in nkai/dist/, with an automated CLI migration script (tools/upgrade_sidecar.py).
Pros: Preserves 100% atomic offline durability. 1-click automated upgrades via AST/DOM hook replacement. Zero tag drift.
Cons: Requires maintaining a small Python migration script.

5.2 Systematic 4-Lens Tradeoff Evaluation
Perspective Lens Model 1: Decoupled Shared Core Model 2: Manual Inlining Model 3: Hybrid Pragmatic Standard
🌍 Real-World Ergonomics High risk of broken styling when files are moved to artifacts folder or shared with team. High human friction. Editing 100KB files to upgrade headers causes token burn and fatigue. Optimal. Single command python upgrade_sidecar.py --target board.html upgrades in seconds.
🎛️ Audio Software Industry Similar to external DLL dependencies; crashes host if a relative path moves. Monolithic plugin binaries with zero update path; hardcoded assets that never modernize. Standardized factory presets + dynamic schema migration (like FabFilter Pro-Q2 ➔ Pro-Q3 state import).
🏛️ Wider SOTA Systems Classic symlink / relative script patterns that break across container boundaries. Static unversioned HTML files typical of legacy static sites. Adopted by Astro/Vite (single-file bundles with migration codemods) and Jupyter Notebooks.
🏆 Best Practices & Sustainability Fails zero-dependency offline invariant. Dead links rot silently. High technical debt. Different sidecars drift on different obsolete versions. Clean SemVer tracking in Git. Automated AST verification guarantees zero content loss.
